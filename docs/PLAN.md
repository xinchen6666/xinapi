# xinapi 单机 Docker 开发与部署计划

版本：Docker v1 · 2026-11-22 UTC · 目标仓库：[xinchen6666/xinapi](https://github.com/xinchen6666/xinapi)。本文件是唯一活动路线图；做到了哪一步以[项目状态](STATUS.md)为准。**计划里的命令和验收均不是执行结果。**

## 产品交付标准

管理员从 New API 的一个入口完成「添加 Clash 订阅 → 核对节点 → 选定出口 → 授权上游账号 → 给成员分组授权」。成员只持有平台 Key，能查看自己的用量；不能接触订阅链接、节点秘密、上游令牌或管理接口。朋友小团队非商业使用，本版不交付支付、Kubernetes 或 Helm。

从同一仓库的一个可追溯版本，全新 Linux 主机能用 Docker Compose 启动五个服务：New API、单副本 CPR（含受管 Mihomo 子进程）、PostgreSQL 18、New API Redis、CPR Redis。两应用使用不同的数据库和数据库用户。公网仅提供指向 New API 的 HTTPS 入口。真实配置、密钥、备份和实际账号不随源码分发；可提交不含秘密的配置模板。完整部署与回退顺序见[部署设计](DEPLOYMENT.md)。

| 里程碑 | 成员或管理员实际看到什么 | 通过门槛 |
| --- | --- | --- |
| 仓库与基线 X01–X04 | 新克隆能从源码构建两个镜像并启动空环境 | 远端提交可核；没有秘密和遗漏源码；服务隔离且可重启 |
| 第一版演示 X05–X07 | 管理员能粘贴一份自造订阅，预览差异、保存、再次刷新 | 不用真实账号；普通成员被服务端拒绝；改名不丢节点身份 |
| 账号出口 X08–X10 | 账号获得稳定代理入口，可以验证、切换、暂停 | 两个受控出口分别可观察，所有相关后台请求也不回退直连 |
| 团队使用 X11–X15 | 管理员完成授权，成员能用自己的平台 Key 多轮调用 | 两管理员、两成员隔离；协议、异常和计量有证据 |
| 交付 X16–X18 | 在新的单机环境可以安装、备份、恢复、升级并交给下一人 | 版本、运行状态、维护中断、测试范围和未验证项可复核 |

## 每步的工作与 Git 约定

1. **开始。**核对仓库、分支、用户授权与前置任务。在状态表登记任务号、负责人、范围；从[工作日志模板](worklog/TEMPLATE.md)建立 `docs/worklog/Xnn.md`。入口、公共数据合同和迁移编号由集成人员单写。
2. **实施。**按下面的顺序做一个可演示的改动；维护相应源码、迁移、配置样例、测试和操作说明。过程中确认的设计变更写入[决策记录](DECISIONS.md)，影响以后接手的长期事实才记入[项目记忆](MEMORY.md)。
3. **验收。**在本步日志记录真实命令、版本、环境、预期、结果、失败与修复、未执行项、回退点。在[验收矩阵](VALIDATION.md)索引脱敏证据。`not_run`、仅编译、健康检查成功均不能替代功能验收。
4. **交接。**更新[当前状态](STATUS.md)与[交接单](HANDOFF.md)。未结束也需写当前修改、最近一次失败、剩余任务和可恢复动作。换 agent 不依赖聊天历史。
5. **同步。**X01 空仓库首提交到 `main`；以后在 `task/Xnn-简述` 分支用 `类型(模块): Xnn 动作` 提交**实际源码＋测试＋本步记录**，每步推送到 `origin`。核对 `git ls-remote origin refs/heads/<分支>` 与本地 SHA，PR 写测试结果和证据；通过检查后按仓库规则合并。报告区分「本地提交」「远端分支已核对」「已合入 main」。Git 提交无需写入自己的 SHA；用后续回执或 PR 链接关联。
6. **出现故障。**验收不满足不改 `done`；推送失败保留本地提交及分支，写入错误类别和重试步骤；未知投递结果先查远端。非快进冲突先 fetch 和比较，不以强推、重写用户历史或更换仓库解决。推送不触发真实服务器部署。

## 可执行任务

<a id="x01"></a>
### X01 建立项目与发布基线

**前置／范围：**用户确认的远端、项目根目录；只做 Git 与公开文档。确认目录没有其他根 Git、复查远端 ref；如果远端已出现提交，保留并基于其历史合并。

**操作：**先设置忽略规则和唯一 `origin`。原地换掉旧计划，迁移入口、任务索引、记忆与交接，保留历史证据。暂存前逐件列白名单，消除指向本机快照的必要链接；第一笔提交不导入业务源码。把当前检查及推送结果写入[本步日志](worklog/X01.md)。

**验收／恢复：**计划、状态与验收对应，公开克隆所需文档齐全；审阅暂存文件、链接和秘密扫描，再核对 GitHub SHA。远端不可写时保留本地版本，标明「未同步」；不删用户资料。

<a id="x02"></a>
### X02 固定源码、依赖与许可

**前置／范围：**X01；`services/new-api/`、`services/codex-proxy-rs/`、第三方说明与[上游清单](UPSTREAM.md)。

**操作：**从已核对的完整上游提交导入源码、构建锁文件和必要资源，用普通受控文件组成单一仓库。可选子模块逐个判定是否必需，必需部分固定版本并验证干净检出；不添加父仓库之外的个人 fork 依赖。列出 Cockpit 的订阅下载、纯解析、引擎及稳定入口的逐文件来源，区分直接采用、适配和不采用；移除桌面层耦合，不移植第二个模型网关。登记 Mihomo 平台、版本、来源、摘要和对应源码获取方式，不提交运行时二进制缓存。

**验收／恢复：**源码树不是意外的 gitlink；在干净克隆核实锁文件与构建输入。按组件保留许可、署名和修改说明；混合分发条件未核清的部分只记录接口，暂缓复制/发布，不给整个仓库误贴一种许可证。回退到最近验证的上游版本，不覆盖己方改动。

<a id="x03"></a>
### X03 复现构建，建立持续检查

**前置／范围：**X02；两个服务镜像构建、CI、锁文件。先分别复现未改业务逻辑的上游构建，固定 Go/Bun 与 Rust/pnpm 的版本，记录目标平台。镜像标注来源提交，以版本/摘要识别，不用 `latest` 判断通过。

**操作：**建立按变更路径触发的编译、格式、单元、文档链接和秘密扫描；任务变更需要相应日志。构建缓存不作为构建输入。使用不含秘密的测试凭据和受限工作流权限。含上游 GORM 模型改动时，New API 在 SQLite/MySQL/PostgreSQL 上验证，不因部署选 PG 而删上游兼容性。

**验收／恢复：**从干净工作树构建两个可运行镜像，保存构建命令和 CI 链接。缺依赖、平台不符和基线问题单列，不通过修改业务逻辑让基线虚假变绿。失败保留可复现构建日志。

<a id="x04"></a>
### X04 启动最小五服务环境

**前置／范围：**X03；根 Compose、开发配置、初始化脚本与空测试卷。建立 `newapi` 和 `cpr` 两个逻辑库及隔离权限、各自 Redis。固定秘密经本机受保护文件注入，配置样例只含变量说明。为宿主目录权限、空卷初始化与保留卷重启分别编写校验。只对本机发布 New API 端口。明确两层管理员引导：团队管理员登录 New API；部署者通过受限内网引导 CPR 并安全地给 New API 后端配置管理凭据，不把 CPR 控制台或凭据交给成员。

**验收／恢复：**`docker compose config --quiet`、`docker compose up -d --build --wait` 在隔离开发环境通过；检查 `/api/status`、CPR `/readyz` 及实际服务认证。宿主外不能访问 CPR、PG、Redis 或代理端口。保留卷重复启动不改密码、不清空库；初始化不完整则停止并提示补救，不运行破坏性重置。

<a id="x05"></a>
### X05 New API 管理员只读入口

**前置／范围：**X04；New API 原生 React 页面、Go 管理适配层、CPR 只读接口合同。增加「账号与出口」菜单和只读列表。Go 固定内部服务地址、校验 `AdminAuth` 和操作权限，裁剪账号/代理列表的返回字段；管理 Key 只存后端，不做任意路径透明转发。

**验收／恢复：**管理员看见空、成功、加载、错误状态；未登录、普通成员、模型 API Key 直接访问时均被拒绝，且无 CPR 管理调用。检查浏览器、错误与日志不含秘密。适配失败可关闭入口，原 New API 页面不受影响。证据对应 V11、V13。

<a id="x06"></a>
### X06 首个可用演示：粘贴订阅并预览

**前置／范围：**X02、X05；无桌面依赖的 Rust 下载/解析接口、管理预览 API、React 表单、模拟订阅源。先用自造 YAML、JSON、URI 列表及其 Base64 包装；逐节点识别协议、展示名称和错误。对 HTTP 型 provider 限资源量、深度和跳转后物化为具体节点。默认 HTTPS，测试源作显式例外；复核跳转和实际目标，限制解压后大小与超时，不执行订阅给出的规则、脚本、监听、文件路径或 controller 配置。

**验收／恢复：**管理员粘贴测试链接能看见准确数量、可用项及不支持项；超限、下载失败、解码失败返回脱敏错误。预览不启用账号、不持久发出半份配置；有明确部分解析时须显式确认可接受的范围。保留脱敏 fixture 与 V01–V03。此里程碑不需要真实上游账号。

<a id="x07"></a>
### X07 快照、刷新与迁移

**前置／范围：**X06；CPR Store、Admin、来源编辑和差异确认。建立来源、成功快照、本地节点 UUID、不可变连接版本；来源 URL/节点认证按秘密保存，比较指纹不输出明文。保存时复核预览版本，记录原子发布。相同配置且唯一对应才承接旧身份，名称/排序不是主键；同名换地址/凭据、重复歧义分别作为候选或人工审核。

**验收／恢复：**改名后绑定不变；拉取失败保留最后成功配置并显示陈旧；完整成功快照确认缺失时，绑定投影变为不可用，不自动选别人（此步验证状态，实际网络停发在 X10 验证）；旧的并发刷新不能覆盖新批准值。验证空库和既有库迁移、重复启动幂等及备份恢复。保存 V04、V05。

<a id="x08"></a>
### X08 接入和监督 Mihomo

**前置／范围：**X07；CPR Host、引擎构建、稳定本地入口。首版在 CPR 容器中执行固定版本、校验摘要的 Mihomo。以受限权限生成最小配置，为需要出口的账号/授权预留项建立稳定入口和独立进程；同账号启动串行，设置启动时限、并发与资源上限，异常退出可回收。不上 TUN、不挂 Docker socket、不开放通用代理端口。

**验收／恢复：**验证端口占用、启动认证、正常关闭、异常退出、宿主重启均不留下串号入口。端口冲突时停发或经版本化流程同步修正，不私自换端口。记录单/双引擎的 RSS、CPU、冷启动与 PID；以观测确定容量。留 V06、V07 和对应制品摘要。

<a id="x09"></a>
### X09 账号绑定及换路

**前置／范围：**X07、X08；CPR 管理用例、受管路由和连接池。账号 → 代理关系只由 CPR 的 `outboundProxyId` 保存。受管路由持有稳定入口、具体节点版本、出口代次与观测。管理员探测并批准新版本后才发布。准备候选时保留旧可用版本；对生效状态未知的写入按 operation ID 读回对账，不能假设 Go 库、CPR 库和引擎共享一个事务。

**验收／恢复：**断开候选、提交冲突或进程重启后均能说明实际绑定。稳定代理 URL 之下，切换后新的 HTTP/2 请求及 WS 新轮次不能复用旧节点；在途流按选定策略排空或显式中止。节点名/IP 观测分别显示。记录 V04、V05、V07、V10。

<a id="x10"></a>
### X10 严格出口和故障停发

**前置／范围：**X09；CPR 账号事实、Store 投影、Provider、主动任务和 egress。对托管账号区分「允许发送」「必须出口但当前不可用」，不把禁用/解绑投影为可用的部署默认网络。逐项接通服务端 OAuth 交换、令牌刷新、quota、模型目录、资料、推理 HTTP/SSE/WS 的发送前检查。权限收紧同时作用于已有连接上的新操作。

**验收／恢复：**受控双代理、可记录的默认出口和模拟上游下，停引擎、删除代理、绑定损坏、读取失败、后台刷新均不导致默认出口收到账号流量。只有恢复已批准绑定后才重新准入，不以临时直连恢复可用性。形成按请求类型的 V08–V10 对照证据。

<a id="x11"></a>
### X11 管理员 OAuth 与回执恢复

**前置／范围：**X05、X09、X10；New API Go、CPR 新增只读完成回执，及授权表单。先预留并验证路由，再发起 CPR OAuth；服务端操作记录绑定管理员、登录会话、目标账号、provider、代理版本、期限。提交回调时复查角色、owner 和版本，由 CPR 验证 state/PKCE 并交换一次。浏览器登录走浏览器自身网络；需要同一出口时由管理员使用受保护的授权浏览器路径。不要让 BFF 抓取回调 URL。

**验收／恢复：**A 的流程不能被 B 完成；过期、改绑或撤权不通过。模拟“CPR 已提交、BFF 响应丢失”和 BFF 重启，查询已有确认回执不会再次兑换 code。缺失/过期回执显示 `unknown`，不根据账号列表猜成功；重新授权必须是明确的新操作。无引用预留路由才可回收。记录 V12。

<a id="x12"></a>
### X12 管理员页面闭环

**前置／范围：**X05–X11；New API 菜单、页面、BFF 白名单。沿原组件与 i18n 实现订阅来源/刷新差异、节点测试、出口绑定、账号授权与重新授权、分组、额度刷新、引擎状态、审计。敏感操作显示影响并要求确认，用同一请求 ID 关联 New API 实际操作者与 CPR 服务主体。无广义管理反代、凭据导出或原始配置展示。

**验收／恢复：**管理员不用第二套后台能完成产品流程；普通成员直接请求写接口同样失败。保留脱敏的空/错/加载/部分成功、浅深色和窄屏实际截图。变更冲突重读差异，不以重试覆盖他人设置。记录 V11、V13、V14。

<a id="x13"></a>
### X13 成员注册、分组和内部身份

**前置／范围：**X04、X12；New API 权限与转发适配、映射持久化。新注册成员默认没有上游访问权；由管理员授组。按已验证的成员 ID 与权限范围选择服务器持有的 CPR Client Key。只绑定显式允许组，注意原生空组可能代表全部账号；无授权时直接拒绝。提供创建、转组、撤销、重试和对账路径，不复制 OAuth token。

**验收／恢复：**两成员使用相同 session、thread、cache key 也不能串上下文，不能续接对方 response；空授权、封禁、撤销后包括既有 WS 下一轮都受控。映射故障不回退到全站公共 Key。有关 New API 数据模型的改动验证三种上游数据库。记录 V15。

<a id="x14"></a>
### X14 模型数据面和成员用量

**前置／范围：**X10、X11、X13；普通 OpenAI 兼容渠道、SSE/WS 流和用量可观察性。New API 到 CPR 用服务根地址及内部 Client Key，不重复拼 `/v1`，也不使用直连订阅的 Codex 渠道。先测非流 Responses，再测流、WS、多轮和工具。成员配额/用量归 New API，CPR 看账号容量；明确一层负责哪类重试。

**验收／恢复：**可由请求 ID 串起成员、请求、账号和出口的脱敏记录；上游 401/429、取消、中断、缺失 usage 不会导致已交付内容被盲目重放。已确认、估算、未知用量分开。记录 V16、V17，不做支付流程。

<a id="x15"></a>
### X15 系统集成与真实出口验收

**前置／范围：**X12–X14；跨服务测试、脱敏证据。先运行“两管理员、两成员、两测试账号、两记录出口”的本地矩阵，再使用明确授权的测试账号/代理做公网验证。分别标明模拟源与真实源；浏览器、服务端交换、刷新、推理和额度查询分开测。覆盖并发、断网、重启、节点丢失和公网 IPv4/IPv6 漂移。

**验收／恢复：**不同端口/节点名不是不同公网 IP 的证据。所需地址族不支持时记录实际能力和适用范围，不能硬写双栈成功。任一路径泄漏默认出口则停用相应账号链路并修复。复核 V01–V18，未具备真实验收条件的标 `not_run`。

<a id="x16"></a>
### X16 全新单机安装与首次使用

**前置／范围：**X04、X12–X15；根 Compose、受保护的配置生成、反代样例、运维手册。按[Docker 部署设计](DEPLOYMENT.md)从版本或候选提交构建，准备五服务网络/卷/权限，验证就绪后再开入口。引导设置首个管理员、载入测试订阅、批准节点、授权账号并授予测试成员。优先在干净测试机执行；实际生产机需明确指定。

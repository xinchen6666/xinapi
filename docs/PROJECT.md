# 项目需求与边界

更新：2026-11-22 UTC。来源：用户对小团队范围、单机 Docker 和 GitHub 交付的确认。需求确认不等于下面每个技术选择均已由用户批准；实现选择参见 [决策记录](DECISIONS.md)。

## 用户已确认

| ID | 要求 | 验收指向 |
| --- | --- | --- |
| R01 | 自己和朋友的小团队使用，不做商业付费 | 成员使用不依赖支付；不以收费平台需求扩大本期范围 |
| R02 | 整体页面外壳以 New API 为主 | 用户和管理员使用同一产品入口；管理页面遵循 New API 组件与路由习惯 |
| R03 | 将 CPR 的账号授权、管理功能接到管理员后台 | 管理员在 New API 内完成授权和账号管理；普通成员服务端无相应权限 |
| R04 | 粘贴 Clash 订阅 URL 后读取相应节点 | 后端拉取、识别、展示节点和逐项错误；不要求成员安装桌面 Cockpit |
| R05 | 不同上游账号可使用不同出口 IP | 账号绑定确定节点；实际出口可验证；路由故障不自动直连 |
| R06 | 可以使用 Cockpit 相关代码，场景为非商业自用 | 抽离必要模块并保留来源、许可与修改信息，不因上一轮商业假设排除该路线 |
| R07 | 每步留下工作记录、验收和交接，换 agent 可继续 | 有唯一状态表、每步日志、决策、验证证据和明确下一动作 |
| R08 | 只做单机 Docker Compose 部署，不做 Kubernetes/Helm | 新主机按部署手册完成五服务启动、恢复与升级验收 |
| R09 | 所有产品代码放入用户已建的 [xinapi 仓库](https://github.com/xinchen6666/xinapi)，每步同步 | 任务代码与记录出现在同一仓库；报出本地与核实的远端提交，不将未推送或仅建分支写成已上线 |

此前“用户购买套餐、支付回调、商业售卖”的优先级已取消。原调研的协议、账号代理、角色与许可证源码事实继续有效。

## 本期产品流程

管理员：登录 New API → 打开“账号与出口” → 添加订阅链接 → 预览节点及差异 → 保存 → 选择节点并测试实际出口 → 新增上游账号并选定该出口 → 发起 OAuth → 在本地完成提供商登录 → 回传授权结果 → 查看账号额度、状态与出口 → 授权成员分组使用。

普通成员：注册／被管理员加入 → 等待管理员授予分组（默认无上游访问） → 使用平台分配的账号权限与额度 → 创建自己的平台 API Key → 调用模型并查看自己的用量。成员看不到节点密钥、上游账号 token、订阅 URL 或 CPR 管理密钥。

“Clash 订阅”是节点列表来源；“ChatGPT 订阅”是上游账号权益，两者在界面和数据模型中使用不同名称。

管理员是平台角色，ChatGPT 上游账号是独立身份。平台管理员登录不代表已经取得任一上游账号的授权。OAuth 登录由账号持有人在提供商页面完成，本系统不收集上游密码。

## 建议的首版范围

- 使用 New API 原生 React 页面承接 CPR 管理能力，不把 CPR Vue 管理页直接嵌入作为最终方案。
- 先覆盖 Clash YAML/JSON 的具体节点、URI 列表与常见 base64 订阅；仅包含 proxy-providers 的配置通过受控的 provider 拉取流程处理。不把远程完整配置直接交给引擎执行。
- 节点分组用于筛选展示；账号绑定具体节点，不绑定会自动选择／故障切换的组。
- 手动刷新先验收。后续可增加项目自身的定时刷新，但本轮未创建任何宿主定时任务。
- 第一批模型链路以 Responses HTTP/SSE 和 WebSocket 为主；其它协议单独验收。
- 复用现有成员额度与用量统计；充值、支付、商业订单不是本期任务。
- 首版确定采用 Linux 单机 Docker Compose；小团队实际容量由测试决定。实际成员数、账号数、节点数和部署系统尚未给出，不写成用户事实。

## 固定出口的可验证定义

“固定”先指账号到内部入口、具体节点及连接参数版本的持久绑定。不同节点可能共用同一公网 IP；供应商可能在相同节点地址后轮换出口。软件可记录和比较观测到的出口、发现漂移后暂停并提示，但仅靠一次 IP 探测不能保证未来每条连接的公网 IP 永远不变。

真正要求长期一账号一 IP，需要节点服务本身提供稳定独立出口。管理界面应区分“路由已固定”“当前出口已确认”“出口漂移／未知”。IPv4 与 IPv6 均应核查。

OAuth token exchange、刷新、额度、目录、资料请求和推理均纳入账号出站路径。外部浏览器登录页面单独受浏览器网络控制；首版采用管理员配置授权浏览器代理的路径并明确标识，内置远程浏览器不在当前首版范围。

## 仍待实施阶段确认的输入

部署 OS/CPU、成员与账号规模、主要客户端版本、真实订阅格式、代理供应商能否提供固定 IP、是否开放或邀请注册。无论哪种注册方式，新成员未授组前均不得访问账号池。这些不阻碍本轮规划，也不作为假装已经确定的参数。真实订阅 URL 和账号凭据只在后续验证需要时通过受保护配置提供，不写进文档。

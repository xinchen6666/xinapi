# 任务工作日志模板

在任务开始时复制为 `docs/worklog/Xnn.md`。不要为未开工任务填空结果。任务定义见[计划](../PLAN.md)，实时状态只更新[状态表](../STATUS.md)。

| 字段 | 开工时填写 |
| --- | --- |
| 任务 ID、标题、负责人、UTC 时间 | |
| 前置任务、起始提交／分支、范围 | |
| 可写目录、接口/迁移归属、明确不做什么 | |
| 用户可观察验收、关联 V 编号 | |
| 回退点及可保留的数据／迁移条件 | |

## 做了什么

按发生顺序写简短事实：改动与原因、受影响文件或接口、实际遇到的失败、处置和还需要确认的事项。记录尝试失败不等于产品通过，不能把计划复制成执行记录。

## 实际验证

| UTC / 执行者 | 对象版本、环境与实际命令／动作 | 预期和实际 | passed / failed / partial / skipped / not_run | 脱敏证据或 CI 链接、缺口 |
| --- | --- | --- | --- | --- |

## 发布与交接

记录 Git 目标仓库、分支、本地提交与远端同步状态，附已核对的分支 SHA／PR／合并回执。当前提交不能自引自己的 SHA：用 Git 历史、PR 或后续回执指向它。推送错误只记类别，不贴密钥或完整服务端响应。同步[验证](../VALIDATION.md)、[进度](../STATUS.md)和[交接](../HANDOFF.md)，如长期事实或方向发生变化，再更新[记忆](../MEMORY.md)／[决策](../DECISIONS.md)。

结尾写清下一项可执行动作、已知故障、未覆盖风险、进行中的进程/任务或“无”。禁止订阅链接、节点认证、OAuth 回调、GitHub 凭据、可用的服务 Key、用户身份或真实公网出口进入公开日志。

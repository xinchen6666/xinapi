## 实现

- 两个固定 GET 接口使用 AdminAuth 和 account_egress:read，后端权限判断先于内部服务请求；沿用个人访问令牌的权限 scope 注册。
- 独立 HTTP client 访问 CPR 固定容器地址，携带后端管理 Key；支持请求取消与超时，跳转保持关闭，环境代理保持关闭。
- Key 从私有普通文件按请求读取；Compose 只读挂载私有目录，生成器兼容原配置并创建 0700 目录。
- 账号输出 id/name/provider/status/enabled/planType/outboundProxyId；出口输出 id/name/enabled/accountCount/hasAuthentication，保留原分页元数据。
- 页面复用 SectionPageLayout、DataTablePage、useDataTable、Tabs、ErrorState，沿用默认移动列表。菜单和路由同时检查角色及读取权限；查询绑定当前用户，权限失效时隐藏数据并清理查询。
- 新增文案及后端控制台消息已覆盖七语。测试文件按用户授权同步 `account_egress` 资源的两处完整对象期望。

## 实际验证

- Linux/amd64，Docker 29.1.3、Compose 2.40.3、Go 1.26.10、Bun 1.4.4；CPR 3.54.2、PG18.7、Redis 8.10.3。最终镜像 `xinapi/new-api:x05-reviewed` 构建成功并接回真实五服务。
- Bun 锁定依赖安装、生产构建、完整源码类型检查成功；本次修改文件 lint 为零 warning、零 error。首轮仅挂载 web 目录导致既有计费测试的跨目录 fixture 解析失败，改用完整源码挂载后通过。
- 现有共享表格分页与移动筛选回归 7 项通过。Go 的 middleware、router 测试通过；authz 其余现有测试通过。
- **测试期望维护：**`TestSetUserPermissionsStoresOnlyOverrides` 的两处完整对象期望原先固定三类资源，新增 `account_egress:read` 后实际返回四类；失败定位在原测试第 149、181 行。按用户明确授权，在两处期望加入 `ResourceAccountEgress: {ActionRead: true}`。维护后在 Linux/amd64、Go 1.26.10 容器内执行 `gofmt -l`（输出为空）、`go vet ./service/authz/`（通过）及 `go test ./service/authz/ ./middleware/ ./router/ -count=1`，三个包全部 `ok`；完整 authz 回归由此转为通过。
- 真实 CPR：账号空列表 200；自造认证代理列表 200，返回五个允许字段，认证标志为 true、关联账号数为零。原管理员及成员凭据继续有效。Key 错误和公开文件权限分别为 503，恢复 0600 原文件后立即返回 200。
- 隔离内部 CPR 夹具：匿名和模型 Key 均 401，普通成员和缺少读取权限的管理员均 403；两接口合计八次拒绝，对应 CPR 管理调用为零。任意路径与写方法也保持零管理调用。
- 白名单实测：账号七字段、出口五字段；23 个自造账号第二页为 3 条，分页元数据保持。CPR 原始凭据、邮箱、地址、出口 IP、错误细节均留在内部；邮箱派生账号名改为稳定 ID 展示。
- 内部服务 401、302、额外 JSON 响应和响应头延迟均转换为安全 503，跳转目标调用为零；响应头超时实测 5 秒。最初误将总时限 8 秒作为头超时期望，按实际 5 秒配置修正验证断言后通过。
- Playwright 1.65.1、Chromium 159.0.8154.6：桌面首屏 20 条、第二页 3 条、出口 3 条，加载骨架、错误隐藏旧数据、重试恢复成功；模拟 HTTP 403 后行、标签和菜单均清除。匿名页面转到登录，成员及缺权管理员转到 403，浏览器列表请求数为零。运行错误和管理秘密泄漏均为零。
- 390×844 移动页面实际宽度 390，滚动宽度 390，真实长度 ID 完整换行。六种 CPR 账号状态映射到七语展示文案；页面标题使用已有移动操作区换行能力。

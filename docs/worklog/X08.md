## 做了什么

- Admin 新增引擎用例：按来源与节点加载当前批准版本的私有连接，入口标识由来源与节点稳定派生，重复启动复用运行中进程。公开视图只含入口地址、进程状态、PID、RSS、CPU、冷启动与稳定失败码。
- Host 新增引擎监督：每入口一个 Mihomo 进程，只监听 `127.0.0.1`；生成最小配置（唯一节点、`MATCH,node` 规则、本机控制面密钥），配置 `0600`。启动前确认端口可用，占用时返回 `engine_port_conflict` 停发入口；就绪探测以入口端口为准，超时或进程退出按失败回收。
- 入口端口成对分配（入口 + 控制面），写入运行数据卷的 `entries.json`；CPR 重启后入口保持同一端口并显示 `stopped`。容量由 `CPR_ENGINE_MAX` 限制，超过时返回 `engine_capacity_reached`。
- 停止先发 `SIGTERM`，超过 5 秒宽限期强制回收；进程意外退出在下一次入口操作时回收槽位，并保留退出原因。进程随监督器释放由 `kill_on_drop` 兜底。
- API 新增 `GET /api/admin/engines`、`POST /api/admin/engines/start`、`POST /api/admin/engines/stop`，沿用管理端鉴权与错误封套；失败原因映射固定机器码与中文提示。

## 实际验证

真实 Mihomo `v1.19.33`（制品锁见 [third_party/mihomo.lock.json](../../third_party/mihomo.lock.json)，按发布包下载后在 CPR 容器内执行），自造 HTTP 节点代理与目标站点位于隔离网络，来源经 X07 流程批准。

| 验证 | 实际结果 |
| --- | --- |
| 启动与冷启动 | 200 运行；冷启动 52ms（首个实例 207ms），PID 有效，RSS 约 42MB，CPU 0.06s |
| 出口 | 经入口请求目标返回 `engine-ok`，节点代理计数 2→3；入口指向唯一批准节点 |
| 隔离 | 入口只监听 `127.0.0.1`；同网络其它容器连接返回 errno 111，CPR 对外端口保持 8080 |
| 配置权限 | 入口目录与 `config.yaml` 实际为 `600`；控制面密钥随机生成且只出现在本机配置 |
| 并发启动 | 同一入口两次并发请求均 200，进程 PID 唯一（636），端口唯一（24102） |
| 异常退出 | `kill -9` 后状态 `failed`，`last_error` 记录信号，PID 清空、端口释放；再次启动复用 24102 |
| 端口占用 | 入口端口被占用时启动返回 409 `engine_port_conflict`，端口保持且状态 `stopped`，拒绝静默换端口 |
| 容量 | 两个实例运行后第三个返回 429 `engine_capacity_reached` |
| 停止 | 200；入口端口与控制面端口均释放 |
| CPR 重启 | 重启后三个入口均为 `stopped`、端口 24100/24102/24104 保持，容器内残留监听清零；再次启动复用原端口 |

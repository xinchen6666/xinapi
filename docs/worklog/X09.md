## 实现

- 追加0047，建立managed_routes与managed_route_operations，outbound_proxies增加route_generation。账号→代理关系仍由provider_accounts.outbound_proxy_id唯一持有，URL为Provider使用的同步投影
- Admin准备候选时读取批准连接，Host用独立预留入口运行和探测，当前账号入口保持。探测完成释放候选进程、登记与私有目录
- 操作使用调用方operation_id幂等，包含expected_generation、期望账号代理ID／URL／revision及来源revision。ready后显式approve，claim阶段固定发布关系，发布完成才推进generation和config_revision
- PG事务原子保存代理、账号绑定、出口代次、审计与applied回执；Host进程切换位于事务外。中断保留applying，GET返回实际路由／引擎及requires_reconciliation，显式reconcile负责确认或恢复
- 发生冲突可恢复原已发布历史连接并终结候选。ready／preparing可显式abort；applied保留确认历史，后续换路创建新operation
- 稳定入口端口和认证保持。发布明确终止旧Mihomo全部隧道，新HTTP/2和WS按独立route_generation选择池；credential_revision保持原语义
- OpenAI HTTP与WS复用键包含出口代次；xAI和Host客户端缓存通过OutboundProxy的值比较自然分代。WS物理连接预算继续按稳定URL共享
- 通用proxy更新／删除／写测试／导入预留保护受管代理，发布期间还保护初次绑定所用普通代理；跨账号借用、发布期改绑、受管账号通用删除与携带入口凭据的账号导出均拒绝

## 自审修订

独立只读复核指出并完成修正：claim后来源变化导致挂起状态难以恢复；来源新批准版本覆盖原路由恢复资格；数据库已提交但回执丢失时跳过运行发布；普通代理写入绕过首次applying保护；账号删除遗留受管引擎；敏感账号导出暴露本机入口凭据；ready候选缺少终结入口。对应路径均有运行证据或静态核对

Host replace按owner串行，旧进程wait完成后才更新本机登记并启动新版本；候选目录回收前验证解析后的绝对路径属于指定引擎根目录。全局锁只持有登记变更，进程等待保持每入口独立

## 真实运行验证

环境：真实CPR、Mihomo v1.19.33、PostgreSQL和Redis；两个正式管理接口导入的停用自造账号；容器节点A/B分别拥有独立内网地址；目标提供HTTP1、TLS HTTP2和WebSocket。所有地址属于隔离网络，公网出口保持待验证

| 场景 | 实际结果 |
| --- | --- |
| 初次准备、批准和绑定 | ready→applied，账号代理ID与受管代理一致，generation=1，实际流量经过A |
| 节点名与IP观测 | 独立字段返回，IP来自目标实际看到的代理连接地址 |
| 断开候选 | prepare返回502、操作failed，原入口和generation保持 |
| 准备B候选 | ready期间原账号流量仍走A |
| 固定入口发布B | 原endpoint／proxyId／凭据保持，generation推进，实际出口变为B |
| HTTP2与WS在途 | 旧流与旧WS均关闭，旧HTTP2新请求得到ERR_HTTP2_INVALID_SESSION；新HTTP2／WS经B |
| 旧候选与重复批准 | 旧generation批准409；同operation重复批准200且generation保持 |
| 凭据版本 | credential_revision保持原值 |
| 来源在applying期间变化 | publish冲突409，reconcile恢复原出口并将操作failed，清除applying |
| 历史固定版本恢复 | 来源随后批准新连接，CPR重启仍按路由已确认历史版本恢复原出口 |
| 客户端未接收批准响应 | GET读回applied；再次approve保持同generation |
| applying时客户端取消并重启 | GET仍applying，显式reconcile完成发布并清除requires_reconciliation |
| 受管proxy普通写与跨账号绑定 | update/delete与借用均409 |
| 受管账号敏感导出 | 409，入口认证保持服务端私有 |
| ready候选abort | failed；初次尚无绑定且候选终结的账号可按普通流程删除，历史操作继续可读，route/engine为null |
| 已发布账号通用删除 | 409 |
| 初次绑定正在applying | 原普通proxy编辑／删除与账号改绑均409，继续发布成功 |
| 单账号独占 | 专用proxy只被所属账号绑定 |

## 运行与能力边界

- 候选准备临时需要一个空闲引擎槽，默认2实例能覆盖单账号换路；双账号同时运行时准备新候选需要相应容量，已有上限继续生效
- 连接策略为显式终止；已有流可能收到连接结束，旧WS connection-local continuation依现有错误／重建流程处理
- 当前X09只覆盖受管路由，完整故障停发与全部后台请求出口由X10承接。真实模型推理、用量与公网业务由后续任务验证
- 普通代理保留原API合同；受管账号专门退役流程后续补齐，当前通用删除返回冲突
- 追加迁移保持既有文件原字节；手工迁移摘要操作按当前用户约定省略。旧X08制品准入继续复用
- 受管操作历史保存审计与读回状态，API返回脱敏endpoint；原始配置、入口凭据、实际账号身份与运行日志只保留在私有目录

## 实现与事实归属

- 0048新增provider_accounts.managed_egress_required，回填已发布受管账号。X09发布同事务将此值置true；解绑、代理停用与旧导入更新继续保留要求
- Core OutboundProxy拥有Account、Reservation或Blocked要求。托管连接缺失、禁用或损坏时保留Some(Blocked)，普通账号继续使用原部署出口合同；策略以共享只读值持有，连接池身份包含其内容
- PgManagedEgressState每次发送核对账号启用状态、持久要求、实际账号代理ID／URL、代理启用状态、代理与路由generation、applying状态和来源节点可用性。来源新批准版本保留原路由历史版本的执行资格，明确停用节点时拒发
- Host在三秒预算内完成数据库校验，再核对实际入口的owner、节点／版本、私有地址、进程及取消／关闭状态。组合根在Provider启动前安装准入能力，重复安装明确失败
- gateway-egress提供admit与admit_account。后者会核对旧客户端创建后账号收紧的当前要求，即使旧客户端保存proxy=None。显式代理继续绕过环境代理与NO_PROXY，Blocked始终返回发送错误
- OAuth pending保存托管策略和出口代次；旧受管pending缺少这些事实时拒绝恢复。新账号授权拒绝借用已归属其他账号的托管入口，后续X11使用独立授权预留流程

## 实际发送覆盖

| 请求类别 | 最后发送检查 |
| --- | --- |
| OpenAI推理JSON／HTTP／SSE／Messages／Live HTTP | cached client命中后、execute/send前检查当前账号 |
| OpenAI WS握手／response.create | 连接预算排队后、拨号后发送认证头前，以及租用socket后的新轮次发送前 |
| OpenAI WS ResponseControl／Live中继 | 控制消息携带冻结账号与代理；泵实际write前再次检查，拒绝即回收；Live每业务帧同样检查 |
| OpenAI OAuth交换／PAT／refresh | TokenClient保存完整代理，实际send前检查；已有账号定时／手动刷新与重授权增加账号级准入 |
| OpenAI quota／subscription／profile／reset／models | 每个实际请求、目录分页与账号端点404目标回退前检查，头像路径单独覆盖 |
| xAI OAuth／refresh／userinfo／JWKS | 已有账号身份贯通到实际send，缓存锁等待后再次检查；新授权通过显式代理准入 |
| xAI inference／catalog／billing／subscription | account binding或完整代理贯通，缓存选定后、发送前检查 |
| Host HTTP／WS／peer | HTTP实际请求前、WS取得writer后每业务消息、peer按账号发送前检查 |

## 自审修订

独立只读复核定位并完成三项修订：新授权借用已有账号托管代理、WS连接预算队列后许可过期，以及有界WS控制消息队列在背压后的实际写入。对应实现分别在Admin创建授权边界、握手permit及dial之后、PumpCommand实际writer之前核对当前准入。

附加边界：托管位置探测保持代理路径，避免向部署默认出口发送相关查询。固定低基数错误保留NotSent／Unavailable语义，推理准入拒绝禁止自动重试；令牌任务可按原退避再尝试，但实际发送仍需重新通过准入。取消／Close等清理行为保持可执行。

## 真实验证

隔离上游记录路径类别、来源节点与请求数量；节点A/B各自转发，默认出口独立记录。使用正式管理接口导入的账号及X09已批准路由，库级程序调用真实Store、Host监督器、Mihomo、OpenAI和xAI公共传输能力，持续复用同一客户端／连接池。

- 16类实际发送：OpenAI quota、profile、models、SSE、WS、refresh、code exchange；xAI discovery、refresh、exchange、models、billing、subscription、inference、userinfo、JWKS
- 主矩阵309次观测，覆盖允许、故障与恢复；补充22次观测覆盖NO_PROXY=*、真实引擎异常退出及恢复，共331次
- 165次故障／收紧调用全部完成拒绝，超时计数零，上游新增请求零、默认出口新增请求零
- 故障包括代理禁用、解绑、generation偏离、URL损坏、账号禁用、route applying、来源节点停用、引擎停止／异常退出、数据库关系读取失败，以及旧proxy=None客户端面对当前托管要求
- 每类故障后恢复原已批准事实，再实测请求重新送达；finally检查确认数据库字段、关系名、来源可用性均恢复，验证进程结束时引擎停止
- 真实网关JSON／SSE数据入口12项通过；默认出口另行发送校准请求，计数确实递增。删除受管proxy保持409，数据库引用约束同样拒绝直接删除；新OAuth授权借用现有owner入口409
- 存量ResponseControl在正常状态下实际送达，代理禁用后新消息拒绝且计数保持；NO_PROXY=*场景仍经显式托管节点发送

“发送观测通过”与“模拟响应业务解析完成”分别记录。xAI授权码交换使用固定拒绝验证器，JWKS夹具缺少有效签名密钥，部分目录／订阅夹具仅提供最小响应；这些结果证明真实transport已发送或已拦截，完整第三方授权成功保持待验证。

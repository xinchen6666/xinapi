# X11 期间服务器资源复盘与清理

日期：2026-11-26，Asia/Shanghai。负责人：lead；source-audit 提供源码副本与远端状态的只读核查。

范围：按用户本轮指令复盘磁盘、内存压力，清理可再生文件与已完成阶段的验证容器，梳理 GitHub 与本地保留职责。X11 业务开发由原会话继续；本轮维护文档与协作规则为独立写入范围。

## 故障原因与证据

1. 直接触发因素是开发构建期间的内存峰值与磁盘空间耗尽。用户提供的上一轮处置记录显示：系统盘曾达 100%、可用内存约 870 MiB，Rust 调试构建目录约 14 GiB，Rust 与前端构建同时运行。上一轮已清理约 9.4 GiB 构建文件与约 552 MiB 软件包缓存，并启用压缩交换空间。
2. 本轮读取主机 sysstat 当日历史：北京时间 11:40:26—12:20:16 的可用内存约 0.77—0.88 GiB，11:50:21—12:20:16 的 CPU iowait 约 60.9%—62.0%。同一时段交换空间总量为零，主缺页约 770—820 次/秒，回收扫描持续高位。证据支持内存回收、文件页反复读取和磁盘等待互相加重的判断。
3. 多轮开发产物累积放大了故障。本轮开始时项目约 13 GiB，其中临时运行目录约 11 GiB；Docker 报告镜像逻辑大小约 14.93 GB，容器共 57 个、运行中 33 个。旧 X04/X07 验证栈长期驻留。剩余 Rust 中间目录约 4.8 GiB，历史 Go 编译缓存约 1.1 GiB，另有单个约 993 MiB 的旧 Rust 二进制。
4. 收尾清理和共享主机资源预算在前面开发过程中执行欠充分。大量已完成阶段的产物与验证服务继续留存，重型构建又与服务争用内存和磁盘。

本轮查询的故障时段内核日志中，OOM kill 与内核 I/O error 匹配项为零。历史采样与上一轮处置记录支持上述资源压力判断；各进程在每个时刻的精确峰值仍缺专门记录。实时复测采用正常轻负载，长期高负载另行验证。

## 实际执行

- 清理 Rust 的 deps、build、fingerprint、incremental 目录，保留当前顶层可执行文件。删除前确认编译进程、活动文件描述符和运行容器挂载，取得现有 Cargo 构建相关文件锁。
- 清理旧 Go 编译缓存、npm 下载缓存、浏览器重复下载分片和压缩包；保留正在使用的浏览器安装及前端依赖。
- 清理 X03、X06、X07、X08 的闲置二进制副本。
- 清理四份 X02 历史验证克隆和一份 New API 研究缓存，均已确认工作树洁净。保留主仓库与独有本地分支。
- 停止 20 个旧 X04/X07 验证容器，连同此前停止的旧验证、构建容器，共移除 42 个容器。各旧环境的数据卷和私有配置继续保留。
- 删除 14 个已解除引用的旧应用镜像标签，包括 X 阶段历史镜像和 Agent2API 两个旧版本；Docker 清理了超过 24 小时的闲置悬空镜像。
- 删除约 539 MiB、容器引用为零的旧 Cargo 下载缓存卷。当前 Cargo、Go 模块与 Rust 工具链缓存继续服务 X11 开发。

上述文件路径清理前报告的分配空间合计约 8.79 GiB。硬链接、镜像共享层和同时进行的开发写入会影响相加结果，整机净释放空间以清理前后的文件系统读数为准，约 12 GiB。

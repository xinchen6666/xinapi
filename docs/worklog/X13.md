# X13 成员授权与内部身份

- 开工：2026-11-27（Asia/Shanghai）；负责人：lead 集成，成员持久授权、固定 CPR 渠道发送、用户授权界面分域实现。
- 起点：X12 已经审阅修订并通过普通合并提交进入 `main`，[PR #12](https://github.com/xinchen6666/xinapi/pull/12)。工作分支 `task/X13-member-access` 从更新主干创建；原主工作树维护编辑保留。
- 范围：管理员按成员显式授予 CPR 账号组；每次授权代次持有服务端专属 Client Key。缺授权、空组、撤权、成员停用或映射待确认时，内置 CPR 渠道拒绝新请求。New API 平台分组及普通外部渠道保持原语义。
- 数据与调用：本地成员授权表先提交代次和待确认状态，网络调用位于事务外；旧内部 Key 禁用后按非空组创建新 Key，凭据仅服务端密文保存。结果含糊时显式对账，浏览器只查看业务字段。
- 成员请求：部署配置固定渠道 ID 与 CPR 服务根地址；最终发出前核对目标和成员当前代次。已建 Responses WS 每轮重查授权。托管 Key 的续接要求已确认的归属和当前账号范围，记录缺失或读取故障时提示携完整历史发起新轮。
- 验证：重型构建串行、Go 两路；真实 SQLite／MySQL／PostgreSQL 核对持久层行为，以两成员和自造上游验证授组、撤权、续接与 WS。正式测试文件保持原样。

- Go 1.26.10：生产 New API 构建通过；指定既有权限用例及 Origin／PAT 路由回归通过。正式测试文件保持原样。

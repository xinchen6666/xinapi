- 开工：2026-11-27（Asia/Shanghai）；负责人：lead 集成，外置联调执行器与部署路径复核分域处理。
- 起点：X15 经复审以普通合并提交进入 `main`。从远端 `main` 新克隆，并建立 `task/X16-single-host`；原工作目录的维护、首页和说明文档编辑保留。
- 范围：复用五服务 Compose、明确镜像、长期私有配置、单机 nginx HTTPS 与只读 Mihomo 挂载，完成部署者导入 CPR Key、团队管理员首次设置、节点审批、受控授权、成员授组、HTTPS 首次 JSON／SSE／WSS 调用。
- 写入：Compose 部署示例、安装及交接文档与脱敏证据。正式测试、原有持久数据及公开发行保持原范围。

## 实施与结果

- 从已合入 [PR #15](https://github.com/xinchen6666/xinapi/pull/15) 的 `main` 新克隆，[主干镜像检查](https://github.com/xinchen6666/xinapi/actions/runs/45945333027)通过。新克隆沿安装手册准备一套空卷；第一次验证发现严格 `umask` 下公开挂载脚本权限不足，按手册调整公开文件模式后，在另一空卷重走初始化，保留原卷。
- 从新克隆构建本地 `xinapi/new-api:x16-local`（Go 1.26.10／Bun 1.4.4）和 `xinapi/cpr:x16-local`。CPR 常规镜像构建遭遇 Git 依赖传输超时，改由 Rust 1.99.1 两任务从同一锁定源码编译集成二进制，再与既有镜像配方的运行层及前端打包，CLI 报 `3.54.2`。本机镜像用于安装验证，公开制品与优化发行另行安排。
- Linux amd64、Docker 29.1.3／Compose 2.40.3、PostgreSQL 18.7、Redis 8.10.3、nginx 1.24.0 与 Mihomo 1.19.33 实测。既有生成器重复运行保留私有配置；`tools/start_compose.py` 报告五服务就绪，实际端口发布仅 New API 回环端口，CPR 内 Mihomo 为只读挂载。
- Chromium 149 通过受信测试 CA 完成空库首次设置和登录，收到 Secure、HttpOnly、SameSite=Strict 会话 Cookie。部署者在 CPR 内部确认首次签发状态，签发后用 `install -m 0600` 显式导入；后台按原挂载热读。经 HTTPS 审批来源、验证节点、完成受控 OAuth 单次交换、设置账号组并为两成员显式授组，跨源管理请求被拒绝。按系统分配的渠道 ID 更新私有 env，并仅重建 New API。
- 受信 HTTPS JSON、SSE 与 nginx WSS 均通过。实跑同一 WSS 的两轮续接与撤权后下一轮停发；工具往返、账号组隔离和用量记录核对通过。见 [18 条首用结果](../evidence/X16-installation.json)、[首次设置](../evidence/x16-first-setup.png)及[授权账号](../evidence/x16-first-authorized.png)。正式测试源码保持原样。
- 安装流程和配置见 [单机安装手册](../INSTALL.md)，交付 [PR #16](https://github.com/xinchen6666/xinapi/pull/16)。隔离自造账号、节点与授权回调仅用于验证；公网第三方登录、生产部署、公开制品分发分别留待授权。

## 实施与结果

[X16](https://github.com/xinchen6666/xinapi/pull/16)复核补充 Docker Engine 28.0.0 最低版本与默认 bridge/NAT 隔离策略，实测 29.1.3 满足条件；[最终 PR 检查](https://github.com/xinchen6666/xinapi/actions/runs/45955618197)通过。普通合并后的[主干检查](https://github.com/xinchen6666/xinapi/actions/runs/45955733999)通过。公共 Git 克隆及源码包下载遇到传输超时，本地改用已审阅结点，远端交付沿更新主干。

两套 X16 实测镜像使用新的候选标签导出，移除候选别名后从压缩包重新载入；原 X16 标签保留。两套应用均可执行 CLI，CPR 报 `3.54.2`。正式发布范围、镜像角色和许可见 [接手说明](../RELEASE.md)。

- 新独立项目、空 PostgreSQL 卷和私有配置使用重新载入的两套镜像启动。Docker 29.1.3／Compose 2.40.3、nginx 1.24.0、PG 18.7、Redis 8.10.3 和 Mihomo 1.19.33。Docker 实际发布只有 New API 回环端口，Mihomo 只读，HTTPS 客户端验证测试 CA 和主机名。
- 走通初始化、首次管理 Key 显式导入、来源审批和节点验证、受控 OAuth 单次交换、组授权与实际渠道 ID 激活。HTTPS JSON、SSE 和 WSS 两轮续接通过；撤权后的下一轮停发，成员用量与消费记录相符。接手手册的 curl 示例独立实跑，得到已完成结果和已确认用量。[脱敏结果](../evidence/X18-handoff.json)列出范围。
- [PR #17](https://github.com/xinchen6666/xinapi/pull/17)交付源码及接手说明。定向候选源码包与镜像包留在本机，按组件保留许可；正式网络服务需向用户提供实际修改版本的对应源码入口。公开制品分发、优化发行、生产部署、真实公网账号／节点，以及 X17 专项演练分别待确认。
